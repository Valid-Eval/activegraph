# Code-graph findings: activegraph and neo4j-ruby-driver

activegraph @51b2e98 (v12.0.1), neo4j-ruby-driver @9198622 (both `lib/`), Graphify 0.9.97, CodeGraph 0.21.0. Written so you can use these answers instead of re-deriving them.

Grades: **[V]** read in source or computed from the graph; **[I]** inference. Nothing here executed the gems or a database, so behaviour claims are from reading code.

Samples are small: read these as directional. Receiver types in the last row are my reading of context [I].

**Read rules that follow:**
1. Rank hubs without `method`/`contains` (`analyze.py hubs`).
2. Trust constant-qualified and implicit-self calls. Treat explicit-receiver same-file calls as noise, even though they're tagged EXTRACTED.
3. A method generated by `define_method` has no node, so its callers bind to any same-named method. `QueryProxy#where` and `Core::Query#where` are generated (`query_proxy.rb:161`, `core/query.rb:171`), so `relationship/query.rb:27` gets 8 inbound edges, of which 1 is right.
4. "Import Cycles: None detected" means nothing here: `lib/` has 0 `imports` edges, because Zeitwerk loads constants.
5. `inherits` targets are unlinked placeholder nodes in these gems (89/89, 54/54). Top-level classes do link (fixture).
6. An `include` of a module reopened across files gets no edge. All 14 internal misses in activegraph are this, and all 81 resolved targets have a unique label. That's why `relationship.rb:13` is absent.
7. In the driver, 4 edges cross `mri`↔`jruby`, which can't both load (the loader pushes `shared` plus one implementation). 3 more `shared`→`jruby` edges are name-binding errors (`format`).

| Idiom | Graphify | CodeGraph |

Small and written by me, so names are often unique, which flatters both tools.

## CodeGraph 0.21.0 on Ruby

Fast (about 0.2 s to index), but edges carry no confidence, and cross-file mixins and superclasses are absent. Its Ruby mapper resolves those through a per-file map (`crates/codegraph-ruby/src/mapper.rs`).

| Target | Callers listed | Correct |
|---|---|---|
| `Base.new_query` | 21 | 13 |
| `QueryProxy#identity` | 24 | 23 |
| `Relationship::Query#where` | 37 | 1 |
| driver `Result#each` | 21 | 1 |

Those last two were picked because they looked suspicious, so they bias low. `analyze_impact` rated `query_run` `low` (1 file), and rated `Relationship::Query#where` `low` while listing 209 impacted symbols, nearly all false. All 37 `Session#run` callers also appear under `UnmanagedTransaction#run`. **I wouldn't use it for change decisions on Ruby at this version.**

## Egress, for these exact modes only

- Graphify `extract --code-only`, `GRAPHIFY_BACKEND=none`: `graph.json` byte-identical with network denied and open; a Python audit hook logged 0 socket events. Sandbox and hook were each exercised against a known connection.
- CodeGraph `--graph-only`: 0 connections by `lsof` polling, which can miss short ones. 6 of 33 tool results differ between identical runs, so diffing is only partial evidence.
- CodeGraph embeddings fetch about 130 MB on first use, then work offline.
- `graph.html` loads vis-network from unpkg.com when opened (SRI-pinned). This harness passes `--no-viz`.
- Base Graphify install uses Louvain, not Leiden.
